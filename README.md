## ILog
Интерфейс для работы с пользоательскими уведомлениями.

## PrintMessage
инмплементирует ILog, выводит сообщения на экран
Удовлетворение принципам SOLID: S,I,D

## OperationRepository
DI контейнер. Хранит операции со счетами, выполненные в рамках сессии, получаетя, что это, своего рода кэш, а значит реализует (условно) паттерн Proxy, для полноценной
реализации не хватает сделать загрузку данных при запуске приложения (из БД
или csv) и реализации механизмов контроля за количетсво и ttl записей
Удовлетворение принципам SOLID: S,I,D

## ListOfCategories
DI контейнер для Категорий. Хранит созданные в процессе работы категории, получается, что это, своего рода кэш, а значит реализует (условно) паттерн Proxy, для полноценной
реализации не хватает сделать загрузку данных при запуске приложения (из БД
или csv) и реализации механизмов контроля за количетсво и ttl записей
Удовлетворение принципам SOLID: S,I,D

## AccountRepository
DI контейнер. Хранит созданные в процессе работы счета, получается, что это, своего рода кэш, а значит реализует (условно) паттерн Proxy, для полноценной
реализации не хватает сделать загрузку данных при запуске приложения (из БД
или csv) и реализации механизмов контроля за количетсво и ttl записей
Удовлетворение принципам SOLID: S,I,D

## IBank
Устанавливает контракт с методами для изменения состояния счета

## Bank
Имплементирует интерфейс IBank. Реализует исключительно операции по изменению баланса счета. Удовлетворение принципам SOLID: S,I,D и GRASP

## IOperationHandler
Интерфейс команд для работы с балансом счета. 

## DepositOperation и CostOperation
Имплементируют интерфейс IOperationHandler. Паттерн Команда
Удовлетворение принципам SOLID: S,I

## BankClient
Класс более высокого уровня. Расширяется посредством агрегации, работает с перечисленными выше классами низкого уровня. Удовлетворение принципам SOLID:
S (спорно), I (спорно), D, O. Реализует паттерн Фасад

## IReport
Интерфейс, объявляет контракт по работе с отчетами

## DisplayReport и ReportToCSV
Наследуются от абстрактного класса BaseReport, который имплементирует интерфейс 
IReport. Удовлетворение принципам SOLID: S, I, D

## IGenerateAccNumber
Интерфейс, объявляющий метод для создания Id банковского счета. Нужен для соблюдения Dependency inversion principle и паттерна открытость/закрытость   
для класса более высокого уровня BankAccount

## BaseWriterCSV
Абстрактный класс, объявляющий методы и атрибуты для записи данных в csv

## CategoryReport, AccountReport, OperationReport
Наследуются от BaseWriterCSV. Пеопредляют методы для работы с конкретными данными
Удовлетворение принципам SOLID: S,L,I

## WriterCsv 
Класс более выского уровня, чем CategoryReport, AccountReport, OperationReport
наследует их меоды посредством композиции и реализует паттерн Адаптер: с одной стороны в него передаютя данные от ReportToCSV, с другой стороны он, используя 
методы CategoryReport, AccountReport, OperationReport преобразует данные и 
записыват их в csv файлы. 

## BankAccount
Cущность банковского счета. Удовлетворение принципам SOLID: S, O, I, D
Реализует паттерны фабричный метод и Строитель

## AccountConstants
Хранение констант для BankAccount, обеспчивает реализацию Dependency inversion principle и паттерна открытость/закрытость для класса более высокого уровня BankAccount

## Category
Сущность категорий
Удовлетворение принципам SOLID: S, O, I, D

## CategoryType
Доступные типы категории

## Operation
Сущность операции с банковским счетом
Удовлетворение принципам SOLID: S, O, I, D

# OperationType 
Доступные типы операций.

## Manager 
Является DI-контейнером, скрывает внутри себя реализацию. Реализует паттерн Фасад
Удовлетворение принципам SOLID: D(не зависит от модулей нижнего уровня) O - условно, с одной сторны для изменения поведения достаточно передать в конструктор другой модуль, реализующий тот же интефейс, с другой стороны, так как это фасад, то могут понадобиться принципиально новые возможности (например 
сохранение данных в БД) и тогда потребуется изменение самого класса Manager
