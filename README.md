BankAccount - сущность счета. 
- Принцип единой обязанности: хранит данные конкретного счета и 
реализует операции, связанные с ним. 
- Удовлетвояет принципу открытости/закрытости (константы, функция генерации)
Так как сущность может быть создана как новая, 
так и инициализирована из сохраненных ранее данных, то логично 
использовать паттерн BUILDER
- initNewAccount - метод фабрика
- BankAccountBuilder - builder, сборка произойдет только через build()
* Я хотел спера просто использовать builder, но так не получалось ограничить 
    возможные варианты создания инстанса только двумя: с именем или
    со всеми параметрами. Поэтому для первого лучая - фабрика, для
    второго - билдер

Category - категория 
- Принцип единой обязанности, открытости/закрытости, d -
* Притом, любя работа с Category будет осуществляться посредством DI-контейнера

ListOfCategories - DI контейнер для Категорий

Operation - операции
- Принцип единой обязанности, открытости/закрытости, d -

Bank - DI контейнер. Вся работа со счетами через него

Интерфейс ILog описывает контракт по соощениям сервиса, сейчас
    используется PrintMessage, который просто печатает на экран,
    но его легко зменить создав новый класс наследник - соответственно
    принцип открытости/закрытости + D 

OperationRepository - хранит историю операций по счету. Намеренно
    не static - потому что, в теории, может понадобиться вести 
    несколько историй операций

IOperationHandler - реализует паттерн команда. Кроме того, удовлетвоярет
    принципам SOID
    На выход дает объект оперция и передает ее исполнителю - Банк

Bank - отвечает лишь за изменение счета, соответственно агрегируетвсю математику
    рабоы со счетом, больше ни за что не отвечает (Наследовани интерфейса
    IBank ) Возможно, лишний уровень абстракции (операцию изменения счета)
    можно повесить и на класс BankAccount, но такой способ позволяет гибко менять 
    алгориы расчета (например, если мы захотим добавить скидку)
    и не придется лезть в класс BankAccount

BankClient - DI контейнер. Внутри него реализуется вся работа со счетами, категориями и прочим
    Фасад. Кроме того, в той или иной мере он является хранилищем

IReport - интерфейс, предоставляющий контракт на получение данных
    счетов и связанных с ними данными

DisplayReport - для данных по счетам, категориям и операциям.
    позволяет выводить данные на экран. 

Manager - фасад
